# Tri-Team King of the Hill: Build Plan

## Gameplay rules (agreed)
- Three teams: **Yellow, Red, Blue**. Players are auto-balanced, and each team spawns at its own base.
- Each base has two vendors:
  - **Gear vendor**: Assault Rifle, Armor.
  - **Vehicle vendor**: Car, Helicopter. The vehicle spawns on the team's pad next to the vendor.
- **Combat Zone (CZ)**: a large circle in the middle of the map.
- **Hotzone (HZ)**: a smaller circle that keeps gliding around inside the CZ.
- **Score tick every 20 s**: each team's weight is the number of its living players in the CZ, and a player in the HZ counts as 2. The team with the highest weight gets 1 point. A tie for the top weight, or nobody in the zone, gives no point.
- **First to 20 points wins.** Then a 15 s intermission. Scores reset, everyone respawns at base, and **cash carries over**. Gear and vehicles reset.
- **Economy**:
  - Small starting cash.
  - Being in the CZ during a score tick pays you.
  - Kills pay you.
  - Being in the HZ when you earn anything gives **+50 %** on that payment.

## Assumptions I made (easy to change in `Config.lua`)
| Item | Value |
|---|---|
| Starting cash | $300 |
| CZ tick pay / kill pay | $40 / $100 (×1.5 in HZ) |
| Rifle / Armor / Car / Heli | $250 / $150 / $200 / $500 |
| Rifle | Full-auto hitscan, 600 RPM, 18 dmg (×2 headshot), 30-round mag, reload |
| Armor | 100 armor points that absorb damage before health |
| On death | Rifle and armor are lost. Cash is kept. |
| Vehicles | One per player. Buying a new one removes the old one. 600 HP. The rifle damages them. They despawn after 60 s empty. |
| Friendly fire | Off |
| Spawn protection | 5 s force field |
| Cash persistence | Carries across matches within a server session, with no DataStore yet |

## Architecture (Rojo project → `.rbxlx`)
```
king-of-the-hill/
  default.project.json      Rojo mapping
  src/shared/               → ReplicatedStorage.Shared   (Config, Remotes, Util)
  src/server/               → ServerScriptService.Server (Main + Services/*)
  src/client/               → StarterPlayerScripts.Client (Main + Controllers/*)
  src/workspace/Map.model.json  generated by tools/build_map.py (visible in edit mode)
  build/KingOfTheHill.rbxlx     ready-to-open place file
```
Server services: TeamService, EconomyService, ZoneService, MatchService, CombatService (rifle + armor + damage), VendorService, VehicleService.
Client controllers: HudController, ShopController, WeaponController, VehicleController (car and heli input).
Replicated state goes through attributes: `ReplicatedStorage.GameState` for scores, next tick time, phase and winner, and Player attributes for Cash, Armor and Zone. The client never decides anything authoritative. Purchases, hits, zone counts and payouts are all server-side.

## Build phases
1. **Skeleton + contracts** (me): project file, Config, Remotes, map naming contract, service interfaces.
2. **Parallel implementation** (Sonnet agents, disjoint files):
   - A: Map generator (bases, vendors, pads, CZ, cover).
   - B: Match, zones, economy, and the HUD.
   - C: Combat (rifle, armor, damage), vendors, and the shop UI.
   - D: Vehicles (car and helicopter) with their controls.
3. **Integrate + verify** (me): selene lint, `rojo build`, and a cross-review of the contracts.
4. **Deliver**: commit, push, and write import instructions.

## Limits
There is no Roblox runtime in this cloud container, so verification is limited to static lint and a successful place-file build. The first real playtest happens in your Studio, using Test → Start with 3 players.
